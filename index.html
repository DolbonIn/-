Part 1: 인지적 핵심

🧠 에이전트 추론 아키텍처 설계

🔗 사고의 사슬 (Chain-of-Thought)

"혼자 생각하기"

⚠️ 한계점: 환각(Hallucination) 및 오류 전파에 취약

🔄 ReAct: 추론과 행동의 결합

"생각하고, 행동하고, 관찰하기"

추론(Reason)과 행동(Act)을 결합하여 외부 도구 및 환경과 상호작용합니다. 이는 추론을 외부 사실에 기반하게 하여 신뢰도를 높입니다.

🤖 Sub-Agent: 역할 기반 전문화

각 단계는 전문화된 역할을 수행하는 'Sub-Agent'에 해당합니다.

하나의 만능 에이전트 대신, 각기 다른 강점을 가진 여러 에이전트가 협력하여 시너지를 냅니다.

Problem-Solver: 초기 솔루션 생성
Solution-Improver: 자가 개선 및 최적화
Code-Verifier: 버그 탐지 및 검증
Report-Evaluator: 이슈 분석 및 우선순위화
Solution-Refiner: 모든 개선사항 통합
Workflow-Orchestrator: 전체 과정 조율

📜 Step 1: 초기 솔루션 생성 프롬프트

정확성과 효율성을 최우선으로

첫 단계의 목표는 추측이 아닌, 명확한 논리에 기반한 완전한 첫 솔루션을 얻는 것입니다.

Step 1 프롬프트 핵심 보기

  • Core Instructions: 정확성/효율성 최우선, 모르면 모른다고 하기, Python만 사용, 사고 과정 설명.
  • Output Format: 문제 분석 → 핵심 아이디어 → 복잡도 분석 → Python 코드 → 엣지 케이스 순서 강제.
  • Self-Correction: 최종 출력 전, 지침 준수 여부 스스로 검토.

✨ Step 2 & 3: 개선과 검증 프롬프트

스스로를 비판하고, 엄격하게 검증하기

✨ Step 2: 자가 개선

"숙련된 프로그래머가 자신의 초안을 비판적으로 검토"하는 역할을 부여하여 논리, 효율성, 가독성을 개선하도록 유도합니다.

🔍 Step 3: 다각적 검증

"IOI 코칭 스태프이자 자동 채점 시스템" 역할을 부여하여, 해결사가 아닌 검증자로서 치명적 오류, 복잡도, 버그, 엣지 케이스를 찾아내도록 합니다.

📊 Step 4 & 5: 분석과 수정 프롬프트

지침을 만들고, 그에 따라 수정하기

📊 Step 4: 검증 결과 분석

"수석 코치이자 최종 중재자" 역할을 부여하여, 3단계의 검증 보고서가 타당한지(Valid Finding) 혹은 오탐인지(False Positive) 판단하고 최종 수정 지침을 만듭니다.

🔧 Step 5: 코드 수정

"숙련된 디버거" 역할을 부여하여, 4단계에서 확정된 수정 지침 목록에 따라 코드의 모든 문제를 해결하고 최적화하도록 지시합니다.

❓ "대화 속에서 길을 잃는" 문제

반복적 개선의 가장 큰 적, 컨텍스트 오염

정보올림피아드 사례 연구자는 반복적인 개선 과정에서 성능이 오히려 저하되는 현상을 경험했습니다. 이는 LLM이 여러 턴의 대화에서 맥락을 잃어버리는 문제 때문입니다. (참고 논문: LLMs Get Lost In Multi-Turn Conversation)

🚨 컨텍스트 오염의 위험

초기 단계의 잘못된 가정이나 불필요한 정보가 누적되어, 후반부 추론의 질을 심각하게 저하시킵니다.

📚 고급 컨텍스트 관리: The Kick!

27점에서 100점으로 이끈 결정적 한 방

해결책은 멀티턴 대화를 버리고, 모든 맥락을 하나의 거대한 싱글턴 프롬프트로 통합하는 것이었습니다.

최종 프롬프트 구조

  • 엄격한 지침 (Core Instructions)
  • 문제 원문
  • 1~5단계의 모든 생성물 (사고 과정, 코드, 보고서)
  • 가장 중요: 27점짜리 코드의 '테스트 결과' 피드백

💡 핵심: 컨텍스트는 양보다 질입니다. 정제된 사고 과정과 명확한 피드백을 하나의 '완벽한 컨텍스트'로 제공하는 것이 성능 폭발의 열쇠였습니다.

🔌 에이전트-컴퓨터 인터페이스 (ACI)

모델 컨텍스트 프로토콜(MCP)을 통한 도구 사용 표준화

문제점 ("N x M" 문제): N개의 모델을 M개의 도구에 연결하기 위해 N*M개의 맞춤형 통합이 필요해 생태계가 파편화됩니다.

해결책 (MCP): AI를 위한 USB-C처럼 작동합니다. 애플리케이션이 MCP 서버로 기능을 노출하면, 어떤 에이전트의 MCP 클라이언트든 표준화된 방식으로 즉시 연결하고 사용할 수 있습니다.

🚀 MCP의 미래: "에이전트 앱 스토어"

Stripe 결제, WolframAlpha 계산 등 전문 기능을 가진 도구들이 서비스 형태로 제공되는 시장이 열립니다. 미래의 에이전트 개발은 최고의 도구들을 가장 잘 조율하는 능력에 좌우될 것입니다.

👥 다수의 힘: 다중 에이전트 시스템

언제, 어떻게 전문화된 에이전트 팀을 구성할까?

정보 올림피아드 문제 해결 과정은 다중 에이전트 시스템의 효과를 명확히 보여줍니다.

✅ 사용 시점

  • 전문화: '코더', '테스터', '리팩토러' 등 명확한 역할 분담이 가능할 때
  • 병렬화: 여러 웹사이트 동시 검색 등 독립적인 작업 수행시

❌ 피해야 할 경우

  • 강한 의존성: 단계 간 공유 컨텍스트가 너무 많아 통신 오버헤드가 클 때
  • 단순한 작업: 단일 에이전트나 스크립트로 충분할 때

Part 4: 20배 성능 달성

🏆 자율적 개선 및 자가 수정

에이전트가 작업을 실행하는 것을 넘어, 자신의 결과물과 프로세스를 능동적으로 개선하는 가장 진보된 기술을 다룹니다.

🔁 궁극의 피드백: 테스트 결과 주입

TDD 피드백 루프의 완성

테스트 주도 개발(TDD)의 'Red-Green-Refactor' 사이클은 AI 에이전트를 위한 강력한 피드백 메커니즘입니다. 정보 올림피아드 사례는 여기에 정점을 찍는 요소를 추가했습니다.

🔑 100점의 비밀: 명시적인 테스트 결과

"부분문제 3, 6, 7에서 시간 제한 초과"라는 명확하고 구조화된 피드백은, LLM이 추상적인 '개선'이 아닌 '시간 복잡도 최적화'라는 구체적인 목표에 집중하도록 만들었습니다. 이는 모호한 자연어 피드백보다 훨씬 강력합니다.

🩹 자가 치유 (Self-Healing) 에이전트

컴파일러와 런타임 피드백의 자동화

TDD를 넘어, 컴파일 오류, 린터 경고, 런타임 예외 등 모든 기계 생성 피드백을 자동으로 캡처하여 에이전트에게 전달하는 워크플로우입니다.

인간: "코드가 틀렸어." (모호함)

기계: "TypeError: unsupported operand type(s) for +: 'int' and 'NoneType' on line 42" (명확하고 실행 가능한 피드백)

이는 에이전트의 작업을 "버그를 찾아라"에서 "42번 줄의 TypeError를 수정하라"로 구체화하여 탐색 공간을 극적으로 좁힙니다.

🤖 메타 에이전트: 재귀적 자기 개선

자신의 프로세스까지 개선하는 에이전트

핵심 아이디어: 인간이 에이전트의 워크플로우(소스 코드)를 직접 작성하는 대신, 상위 수준의 목표만 정의하고 메타 에이전트가 이를 최적의 워크플로우로 '컴파일'합니다.

  • STOP (Self-Taught Optimizer): LM이 자기 자신의 '개선기' 코드를 더 나은 버전으로 만들도록 요청.
  • ADAS (Automated Design of Agentic Systems): 메타 에이전트가 새로운 에이전트를 프로그래밍, 테스트하고 성공적인 설계를 아카이빙.

궁극적인 목표: 정보 올림피아드 사례에서 수동으로 발견한 성공적인 워크플로우 자체를 자동화하는 것입니다.
